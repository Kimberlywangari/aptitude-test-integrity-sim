# Aptitude test integrity: cheat-flagging preparation project

A small preparation project that practises building an integrity / anti-cheating layer
for an online multiple-choice aptitude test: a cheat-flagging baseline, one
well-understood improvement, and a reproducible before/after comparison with an ablation.

**Everything here uses simulated data.** The sittings, the "honest" timing and the
cheating behaviours are all generated by code in this repo, and the cheats are ones I
injected myself. Results describe how the detectors behave on that simulated data only.
They say nothing about real candidates, and this project is not the capstone itself.

Flags are meant for human review. Nothing is auto-rejected.

The detail is in [COMPARISON.md](COMPARISON.md). Every number in both documents comes
from files in `results/`, which are written by scripts and never by hand.

## What was built

- A seeded generator of 5,000 simulated sittings (40 questions each), about 15% of them
  cheating, across four injected cheat types: `too_fast`, `idle_burst`, `focus_loss`
  (repeated focus loss) and `uniform_timing`. Each sitting has a ground-truth label and
  cheat type.
- A fixed 50/50 reference/test split. Everything a detector learns comes from the honest
  sittings of the reference half. Both detectors are scored on the identical test half.
- A **baseline**: flag a sitting if its average seconds per question is below X, or its
  focus-loss events exceed Y.
- An **improved** detector: keep the focus-loss rule, and replace the average-time rule
  with a per-question timing rule (see below).
- Metrics, overall and per cheat type: TP, FP, FN, TN, precision, recall, false-positive
  rate on honest sittings, and F1, with raw counts beside every percentage.
- An ablation of the detector's rules, and a sensitivity check on the z cutoff.
- 51 pytest tests.

## What changed and why

The baseline uses one global "too fast" threshold. That ignores that questions take
different amounts of time, and an average can hide a burst of very fast answers behind an
idle gap.

The improved timing rule works per question:

1. For each question, compute the mean and standard deviation of seconds spent, from the
   honest reference sittings only.
2. For each answer in a sitting, compute `z = (seconds - question mean) / question std`.
3. Count answers with `z < -1.5`.
4. Flag the sitting if that count is at least K.

All thresholds (X, Y and K) come from the honest reference sittings and are set so that
at most 1% of them trip each rule, so the two detectors get the same false-alarm budget
per rule. The z cutoff of 1.5 was fixed before any improved-detector result existed.

## Why these metrics

Flags go to a person, so both kinds of error matter: missed cheats (**recall**) and
honest candidates pulled into review (**false-positive rate on honest sittings**).
**Precision** says how much of the review queue is worth the reviewer's time, and **F1**
is a single summary that weights precision and recall equally. Accuracy is not used: a
detector that flags nobody would be right on 2,125 of 2,501 test sittings (85.0%).
Counts are shown beside percentages because some groups are small, and results are
broken out per cheat type because the overall figure hides a regression.

## Results

Test set: 2501 sittings (2125 honest, 376 cheating). Thresholds learned from 2125 honest reference sittings.

### Ablation, overall

flags a sitting if any rule it contains fires. "A + F" is the baseline and "Z + F" is the
improved detector.

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

| avg_time only | A-- | 169 | 151 | 18 | 225 | 2107 | 151/169 (89.3%) | 151/376 (40.2%) | 18/2125 (0.8%) | 302/545 (55.4%) |

| z_score + focus_loss (improved) | -ZF | 324 | 297 | 27 | 79 | 2098 | 297/324 (91.7%) | 297/376 (79.0%) | 27/2125 (1.3%) | 594/700 (84.9%) |

### What the results show

- On this test set the improved detector flagged 297/376 (79.0%) of cheating sittings
  against 207/376 (55.1%) for the baseline, with 27/2125 (1.3%) honest sittings flagged
  against 35/2125 (1.6%).
- **The gain comes from one cheat type.** `idle_burst` went from 3/113 (2.7%) to 113/113
  (100.0%). `too_fast` and `uniform_timing` got worse (see the per-type table). The
  ablation shows the average-time rule catches those two better than the per-question
  rule, and that using both rules recovers them (A + Z + F: 318/376 (84.6%) recall, at
  37/2125 (1.7%) false positives).
- **The per-question rule alone beats the average-time rule alone**: 239/376 (63.6%)
  against 151/376 (40.2%), with fewer false positives.
- **The result is fragile in the z cutoff.** At 1.0 the improved detector catches
  194/376 (51.6%), below the baseline, and at 2.0 and 2.5 it finds almost nothing beyond
  the focus-loss rule. z-scores of raw seconds cannot get very negative on this data
  (lowest reachable z is -2.04 to -1.68), so 1.5 is close to the edge of what the method
  can use. See Table 8 and the last section of `results/comparison_tables.md`.
- **The lower false-positive count is partly a side effect** of K having to be a whole
  number: the improved timing rule uses about half the false-alarm budget on the
  reference sittings (11/2125 (0.5%) against 22/2125 (1.0%)).
- `idle_burst` at 100% is on a cheat I designed to look like what this rule looks for.
  It shows the code does what I intended, not that it would find real cheating.

## Reproduce

Python 3.14.7 with the versions pinned in `requirements.txt`. From the repo root:

```
pip install -r requirements.txt
python -m pytest -q
python -m src.make_data
python -m eval.run_baseline
python -m eval.run_improved
python -m eval.run_ablation
python -m eval.make_tables
```

- `python -m src.make_data` writes `data/sittings_full.csv` (gitignored, regenerates from
  the seed) and rewrites `data/sample_sittings.csv`, which is identical to the committed
  one.
- The eval scripts build the same data in memory from the fixed seeds, so they do not
  need the full CSV.
- Run the baseline before the improved script: it checks its recomputed baseline counts
  against `results/baseline_metrics.csv`.
- The sample test (`tests/test_split.py`) reads the committed `data/sample_sittings.csv`,
  so that file must be present when running the tests.
- Checked from a fresh clone with a new virtual environment and the pinned requirements:
  all 51 tests passed, and every file in `results/` plus `data/sample_sittings.csv` came
  out byte-identical to the committed ones.

## Known gaps

- **The data is simulated.** Nothing here has been validated on real sittings. Real data
  would be needed to know whether any of this transfers.
- **The cheats are ones I injected myself**, each disturbing a single signal. Real
  cheating mixes signals, and its timing is not necessarily what I assumed.
- **Honest timing is guessed**: pace, wobble, interruptions and end-of-test rushing are
  plausible-looking distributions I chose, not measurements.
- **One seed, one run.** No repeats across seeds and no confidence intervals.
- **The reference is assumed to be clean**, with honest sittings picked using the labels.
  A real reference would be unlabelled and possibly contaminated. Not simulated.
- **Every threshold and the per-question stats are fitted on the same reference
  sittings**, so the reference false-alarm figures are in-sample. The test-set counts are
  the out-of-sample figures.
- **Not built:** z-scores on a log scale (the obvious fix for the bounded left tail), a
  timing-spread feature for uniform/robotic timing, a matched-false-positive comparison,
  any answer-content signals (such as answer patterns or similarity between candidates),
  a contaminated-reference experiment, and any check of how flags fall across different
  groups of honest candidates (for example slow connections or assistive technology).
- **No review workflow.** Flags are just a list of sittings. How a reviewer would use
  them, and what review capacity implies for thresholds, is not modelled.
